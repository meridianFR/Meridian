# Multilingue (FR / EN / PT)

Le site est multilingue via **next-intl** (URLs par langue, FR sans préfixe).
**`messages/fr.json` est la source de vérité.** `en.json` et `pt.json` doivent
contenir exactement les mêmes clés.

## Ajouter du contenu (la règle à ne pas oublier)

Tout texte affiché à l'utilisateur passe par les fichiers de traduction — jamais
de français écrit en dur dans le JSX.

1. Ajoute la chaîne dans `messages/fr.json` (sous le bon namespace).
2. Ajoute **la même clé** dans `messages/en.json` et `messages/pt.json`, traduite.
3. Dans le composant :
   - page serveur (async) : `const t = await getTranslations("Namespace")` +
     `generateMetadata` qui utilise `getTranslations({ locale, namespace })`.
   - composant client : `const t = useTranslations("Namespace")`.
   - liens internes : `import { Link } from "@/i18n/navigation"` (PAS `next/link`,
     sinon le préfixe de langue est perdu en /en /pt).
   - texte avec balise/variable : `t.rich("cle", { tag: (c) => <em>{c}</em>, var })`.
     Note : une **valeur** de placeholder `{x}` doit être une string/nombre ; pour
     injecter du balisage autour, utilise une **balise** (ex. `<hl>{x}</hl>`).

## Garde-fou

```
npm run i18n:check
```

Compare les clés FR ↔ EN/PT et liste ce qui manque ou est en trop. Ce contrôle
tourne aussi automatiquement en **`prebuild`** : un déploiement échoue si une
traduction manque. Donc si tu ajoutes une clé FR sans son EN/PT, le build casse —
c'est voulu.
